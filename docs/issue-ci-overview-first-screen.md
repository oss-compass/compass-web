# 社区贡献、社区工程总览首屏优化（2026-11-11）

## 加载顺序

- 所有总览入口共用 useOverviewEntryData，根据 URL 中的 module 只提前请求当前模块的首屏数据；社区贡献的 summary 与其组件代码并行加载。
- 社区贡献 summary 与社区工程 overview 查询在入口和内层组件间复用 Query Key、在途请求及 15 秒内的新鲜结果。社区工程的复用通过 reuseFreshData 选项启用；其他 useCiDatasetsQuery 调用默认仍使用原先的立即刷新行为。缓存失效和显式 refetch 保留。
- 社区贡献保留首屏 KPI、评分分布和闭环 KPI 所需的痛点汇总。排行榜接近可视区域后加载排名趋势；痛点进展、TOP 问题、仓库管理表格按可视区域挂载，TOP 问题查询同时按需启用。指标附录在展开后加载。
- 社区工程保留同一报告快照的评分与痛点数据及 painReportsMatch 校验。痛点进展、TOP 问题和仓库表格按可视区域挂载；痛点趋势随对应区域加载，嵌入报告只有切换到该视图时加载。
- 两个模块的趋势大图、问题详情及 CI 详情表格按打开操作加载。评分卡片使用稳定的 reportHref 回调与 memo 边界，减少下方区域加载、弹窗操作导致的重复渲染。

## 截图、滚动和兼容

- captureMode 或 expandAllTeams 立即挂载下方区域；社区贡献 data-issue-weekly-ready 保留原有数据条件，并增加延迟组件代码的就绪条件，避免周报在代码尚未加载时截图。
- DeferredReportSection 在首屏评分内容布局完成后才观察后续区域，避免加载占位较矮时提前触发所有下方区域。已有报告使用的默认行为保留；不支持 IntersectionObserver 时加载全部区域。
- 三个入口外壳移除固定 h-screen 与内部 overflow-y-auto，使用文档页面滚动，解决社区入门同时出现页面和内层两条纵向滚动条的问题。表格内部横向滚动保留。
- 不修改 API、指标口径、历史时间范围或报告页请求，也不修改其他任务管理页面的既有工作。

## 验证范围

仅运行改动文件的 Prettier、ESLint 与限定目录的 diff 检查；按用户要求不运行前端构建、类型编译或测试。已有入口测试的 mock 同步适配新预取 Hook，但未执行测试。

没有浏览器 Performance 和构建包体积的前后实测，尚未部署。发布后需复核单一纵向滚动、首次进入/模块切换、滚动加载、弹窗、截图就绪条件及导出，并在相同浏览器和网络条件下比较 FCP、LCP 和主线程长任务。
